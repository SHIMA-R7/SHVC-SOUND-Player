SHVC-SOUND 最小構成 配線表

Arduino Uno R3 / Nano(ATmega328P・5V) ⇔ SHVC-SOUND 24pin ／ 全17本

⚠ この構成では以下を必ず守る
  • 12Vは一切繋がない。TDA7053Aはソケットから抜き、PDトリガーボードも外す
  • 音声出力はコンデンサを必ず挟む(直結するとDCオフセットでスピーカーを傷める)
  • コネクタにはキー(切り欠き)が無く、逆向きにも挿さる。pin 1 の位置は裏面の手順で必ず確定してから配線する

 共通GND ───────────────────── アンプ付きスピーカー GND
  • 電解コンデンサの+側をモジュール側へ向ける(出力にDCオフセットが乗っているため直結しない)。容量は 10µF〜100µF なら何でもよい
  • イヤホン直挿しは避ける。アンプ付きPCスピーカー、またはオーディオIFのライン入力を使う

配線後 → hw_selftest.ino を書き込み、シリアルモニタを 115200bps で開く。判定は裏面参照。

① 1番ピンの確定 ─ 配線より先にやる

テスターの導通モードだけで確実に判別できる。電源は入れないこと。

なぜ必要か
  • 24pinコネクタは 2列×12・2mmピッチで、キー(切り欠き)が無いため逆向きにも物理的に挿さる
  • 逆向きにすると pin24(VS/+5V) の位置に pin1(/CS) が来る = 電源とGNDが入れ替わりモジュールを壊す

手順 ─ GNDピンを探すだけでよい

手順
テスターを導通(ブザー)モードにし、片方のプローブをモジュールの金属シールド、または基板の大きなベタ面に当てて固定する
もう片方で24本すべてを順に当たり、導通する(鳴る)ピンを全部書き出す
導通するのは pin19 と pin23 の2本だけ。この2本が下の特徴に一致するはず

導通するピンが3本以上ある / 上の並びにならない ここで止める。基準にしたベタ面がGNDでない可能性がある。別の基準点で取り直す
  • 反対の端(pin1/2側)には導通するピンが1本も無いことも併せて確認する。GNDの並びは片側にしか現れないので、これで向きが一意に決まる
  • pin1(/CS)は入力ピンなので、モジュール内部でGNDに落ちてはいない。誤検出にはならない

向きが確定したら、油性ペンでモジュールのpin1側に印を付けておく。

② 診断結果の読み方

hw_selftest.ino / シリアルモニタ 115200bps ／ 何かキーを送ると再実行

まず結論から

シリアルモニタの表示意味
全部 [OK] + ノイズが鳴るハードは完動。音が出ない原因は spc_play.py 側にある
全部 [OK] なのに無音転送も実行も成功している。原因は音声出力側だけに絞れる。コンデンサの極性 / スピーカーの音量 / pin20(/MUTE)がHIGHか を確認

[1] で止まる ─ port0/port1 が $AA/$BB にならない

モジュールが起動していない。表示された値で原因が切り分けられる。

読めた値疑う所
$FFモジュールが応答していない。VCC(18)とVS(24)の両方に5Vが来ているか / GND(19,23)がArduinoと共通か / /CS(1)=GND・CS(2)=+5V か / /RESET(15)がA4に繋がっているか
$00データバスがGNDに落ちている。D0-D7(pin 7〜14)の配線を確認
毎回違う値/RD(A3) か /WR(A2) の配線ミス、または結線が浮いている

[2] で止まる ─ 1ブロック目の転送に失敗

リセットは通るのに書き込みが通らない。D0-D7 のどれかが入れ替わっているか浮いている。A0(pin3)/A1(pin4) の配線も確認する。

[3] で止まる ─ 2ブロック目の転送に失敗

1ブロック目は通るのに2ブロック目で落ちる = ブロック切り替えのタイミング問題。配線自体は概ね正しい。ジャンパ線を短くする、電源にパスコン(0.1µF)を追加する。

[5] でマーカーが $99 にならない

転送は通ったがジャンプが失敗している。

よくある落とし穴

VS(pin24)の繋ぎ忘れ — VCCだけ繋いで動かない例が最も多い
GNDが共通でない — 外部電源を併用する場合は必ずArduinoのGNDと繋ぐ
ジャンパ線が長い — 20cm級を使うとバスが不安定になる。10cm以下にする
音声出力の直結 — DCオフセットでスピーカーを傷める。必ずコンデンサを挟む
D0-D7の順序間違い — D2→pin7 から始まる。D0→pin7 ではない
