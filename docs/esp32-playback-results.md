# ESP32 r0.4のSPC・WAV再生確認

2026-10-04。対象はSHVC-SOUND-ESP32 r0.4、30ピンESP32 DevKit V1、ESP32-D0WD-V3。
今回のファームはArduino-ESP32 3.3.12、`esp32:esp32:esp32doit-devkit-v1`でビルド・書込み確認済み。

## 確認できた動作

- 新しく組み立てた基板でSPCの全66,278バイト転送が3回連続成功（約50秒/回）。
- 各試行後のIPLリセット応答はAA/BB。
- Super Mario Worldのタイトル曲を転送し、ユーザーが音声出力を確認。
- WAV由来のモーニングコール約11.122秒を8kHz・モノラルBRRとして転送し、可聴再生をユーザーが確認。
- WAV診断プログラムはDSP設定後のマーカー98を返した。

全転送成功はIPL ACKの確認を意味し、RAM全体の読み返し比較ではない。
初期の基板では同じソフトで不安定な転送があり、最終的な不良箇所は未確定。
診断経緯は[バス診断](bus-diagnostic-results.md)、成功ログは
[new-board-transfer-2026-10-04.json](new-board-transfer-2026-10-04.json)を参照。

## WAVクリップの再生

現在のESP32ファームを書き込んだ後、`SHVC-SOUND_python`から実行する。

```sh
python -m pip install pyserial numpy
python tools/wav_clip_esp32.py your-audio.wav --port COM5 --rate 8000 --seconds 10
```

入力は非圧縮16bit PCM WAV。ステレオはモノラルへ混合し、指定レートへ線形補間で
リサンプルしてから、既存のBRRエンコーダで変換する。音質と変換速度には限界がある。
BRRの変換はPC上で完了してから転送する。

BRRは$0400以降、サンプルディレクトリは$0300、DSP初期化コードはRAM上端へ配置。
音声が初期化コードへ重なる場合はエラーにして、短いクリップを指定してもらう。
再生は1回で終了する。アンプPWMは0、SHVCのMUTEは実行開始時に解除するため、
以下のアンプを通らない出力を使う。

変換済みBRRがある場合は、同じWAVを同じレートで変換したものを明示する。

```sh
python tools/wav_clip_esp32.py your-audio.wav --port COM5 --rate 8000 --brr-cache your-audio.brr
python tools/wav_clip_esp32.py your-audio.wav --rate 8000 --seconds 1 --no-play
```

`--brr-cache`では`--seconds`による切り出しを行わず、BRR全体を再生する。
`--no-play`はシリアルポートを開かず、変換・サイズ・配置を検証する。
音声ファイルはこの変更に含めない。

## アンプを通さない出力

基板に載せたICはTDA7053（Aなし）で、基板の想定するTDA7053Aとは入力配置が異なった。
音量制御端子2/8の電圧だけではAなしICの動作確認にならない。
内蔵アンプの正常動作は今回の成果として確認していない。

J5は既設のライン出力（1=L、2=GND、3=R）。C14/C15を経由し、U6を通らない。
外部アンプ・アンプ内蔵スピーカーのライン入力へ接続する。

J1を同様の出力として使う場合は、全電源を切りU6を抜いて、ソケットを次のようにつなぐ。

| ジャンパ | 基板上の信号 |
| --- | --- |
| U6ソケット4番 → 9番 | AMP_IN_L → AMP_OUT_L |
| U6ソケット6番 → 16番 | AMP_IN_R → AMP_OUT_R |

この接続はC6/C7、R1/R2（330Ω）、C1/C2を通りJ1へ出る。イヤホンを直接駆動する用途ではなく、
外部アンプのライン入力へ接続する。ジャンパを残したままU6を挿さない。
J1の基板ネット割当は1=GND、4=L、2=R。採用したジャック・プラグの実際の接点は導通確認する。

元のr0.4 PCBはU6ソケット12/13番をGNDへ接続しているが、TDA7053/AのIC側では反転出力。
これまでの組立では両脚をソケットから浮かせた。アンプを再実装する際はこの接続を再検討する。
部品表PDFは元BOMであり、この対策を基板変更として反映したものではない。

## 診断コマンド

SPC用ファームの追加コマンドは0B～11。

| コマンド | 内容 |
| --- | --- |
| 0B | ポート書込み |
| 0C | IPL待機中の読書切替試験 |
| 0D | 開始要求4書込みのGPIOラッチ・端子・出力有効状態を記録 |
| 0E | 書込み待ち時間設定（1～1000µs、起動時15µs） |
| 0F | 全256データ値のESP32端子観測 |
| 10 | WRの静的HIGH/LOW保持 |
| 11 | U2経由の8bitデータ静的保持 |

保持試験はSHVCを抜いた状態で、`hold_wr_diag.py` / `hold_data_diag.py`を対話端末で実行する。
接続は開いたまま維持し、exitで解除する。USB抜き差し・再起動・プロセス終了後は保持状態を
前提にせず、再設定して応答を確認する。ESP32端子の論理状態は後段の電圧や全時間の波形を保証しない。

既存AVRの`pcm_stream.py`などが使う0C/0D/0Eは、この診断コマンドと別の意味。
そのストリーミングツールを今回のESP32ファームへ直接接続しない。
長時間ストリーミング、ステレオWAV、別基板・別曲全般の動作保証は未対応。
既存SPC復元スタブによるRAM $FC88-$FFBFの上書き制限も残る。
